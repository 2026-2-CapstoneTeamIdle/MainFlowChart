# 카드 덱 구성 | Feature Validation Checklist

Feature 07 · 총 30개 검증 항목

대상 모듈: DeckSystemModule (덱 편집 UI, 카드 추가·제거 기능은 별도 구현 필요)

검증 상태: 전 항목 미실행 · 실제 게임 동작 검증 결과가 아님

판정값: PASS / FAIL / UNVERIFIED / NOT_APPLICABLE

적용 원칙: 사용자 요구사항에 없는 선택 기능은 NOT_APPLICABLE로 처리하고 이유를 기록

## 덱 구성

- [ ] 01. 게임 시작 시 초기 덱이 정상적으로 생성된다.

- [ ] 02. 덱에 포함된 카드 데이터가 누락 없이 등록된다.

- [ ] 03. 카드의 ID, 이름, 비용, 효과 데이터가 정상적으로 설정된다.

- [ ] 04. 덱 편집 기능에서 카드를 추가하면 덱에 반영된다.

- [ ] 05. 덱 편집 기능에서 카드를 제거하면 덱에서 제외된다.

- [ ] 06. 덱에 추가할 수 없는 카드가 규칙에 따라 제한된다.

- [ ] 07. 덱의 최대 카드 수가 설정된 제한을 초과하지 않는다.

- [ ] 08. 덱 구성 완료 시 선택한 카드 목록이 게임 시작 덱에 반영된다.

## 카드 뽑기 및 관리

- [ ] 09. 게임 시작 시 설정된 초기 손패 수만큼 카드를 뽑는다.

- [ ] 10. 드로우 시 뽑기 더미의 카드 수가 감소한다.

- [ ] 11. 드로우한 카드가 손패에 정상적으로 추가된다.

- [ ] 12. 드로우 결과로 동일한 카드 객체가 의도하지 않게 복제되지 않는다.

- [ ] 13. 손패에서 카드를 버리면 버림 더미로 이동한다.

- [ ] 14. 뽑기 더미가 비면 버림 더미를 재구성하여 드로우할 수 있다.

- [ ] 15. 뽑기 더미와 버림 더미가 모두 비었으면 드로우가 실패한다.

## 카드 사용 및 시스템 연동

- [ ] 16. 카드 사용 시 필요한 자원이 차감된다.

- [ ] 17. 자원이 부족하면 카드 사용이 제한된다.

- [ ] 18. 카드 사용 시 설정된 카드 효과가 실제 대상에 적용된다.

- [ ] 19. 카드 사용 및 드로우 결과가 손패 UI에 반영된다.

- [ ] 20. 게임을 재시작하면 덱, 손패, 버림 더미가 규칙에 따라 초기화된다.

## 완성도 및 회귀 검증

- [ ] 21. 카드 덱 구성 기능의 입력 또는 트리거가 한 번 발생할 때 핵심 동작도 한 번만 실행된다.

- [ ] 22. 카드 덱 구성 기능의 초기 상태가 씬 시작 시 명세된 기본값과 일치한다.

- [ ] 23. 카드 덱 구성 기능의 경계값과 최대·최소 상태에서 값이 허용 범위를 벗어나지 않는다.

- [ ] 24. 카드 덱 구성 기능 실행 중 일시정지와 재개 후 상태와 입력 처리가 일관되게 복원된다.

- [ ] 25. 카드 덱 구성 기능이 여러 대상에 동시에 적용되어도 대상별 상태가 서로 섞이지 않는다.

- [ ] 26. 카드 덱 구성 기능의 성공과 실패 결과가 UI 또는 런타임 상태로 즉시 확인된다.

- [ ] 27. 카드 덱 구성 기능과 승리·패배 조건이 동시에 발생해도 최종 게임 상태가 하나로 확정된다.

- [ ] 28. 카드 덱 구성 기능을 연속 반복해도 중복 이벤트, 유실, 메모리 누적이 발생하지 않는다.

- [ ] 29. 카드 덱 구성 기능 관련 오브젝트가 비활성화되거나 제거될 때 구독과 임시 상태가 정리된다.

- [ ] 30. 카드 덱 구성 기능을 포함한 전체 플레이 흐름을 재시작해도 동일한 입력으로 동일한 결과를 재현한다.
